# 小说→爆款动态漫画 Skill

本 Skill 的目标是**把已有小说/大纲转化为具备平台爆款潜力的动态漫画视频**。完整流程：分镜脚本 → 面板图片 → TTS 语音 → 合成视频。交付物可直接发布或给制作团队二次加工。

## 何时使用

当用户说以下任一含义时，必须使用本 Skill：

- "把这部小说改成能火的动态漫画""做爆款动态漫分镜"
- "按 B 站/快看/抖音的爆款套路，把小说改成动态漫画"
- "给我一份动态漫画分镜文档""把小说做成视频"
- "用 bestseller-novel 的结果来做动态漫画"

---

## 一、输入说明

### 1.1 接受的输入格式

本技能接受以下任一形式的小说内容作为输入：

- **bestseller-novel 技能输出**（推荐）：包含套路画像、题材卖点、章节大纲（章节号+标题+核心事件+爽点类型）、角色描述（人设标签）、章节正文。
- **小说原文**：纯文本小说章节。
- **大纲+角色描述**：结构化大纲配合角色设定。

### 1.2 如何从 bestseller-novel 获取输入

如果用户已使用 bestseller-novel 技能产出小说内容，直接将该输出（或其关键部分：大纲、角色、前几章正文）作为 `novel_text` 传入第一阶段工具。无需用户手动复制——agent 可从对话历史中提取。

---

## ⚠️ 关键约束（必须遵守）

- **严禁使用 `exec` 工具**来生成图片、音频或视频。所有媒体资产的生成**必须且只能**通过下方四个专用工具完成：`comic_storyboard_script`、`comic_storyboard_images`、`comic_storyboard_tts`、`comic_storyboard_video`。
- **严禁编写自定义 Python/PowerShell 脚本**来调用图片生成 API、TTS 服务或 ffmpeg。这些操作已内置在专用工具中。
- **严禁编造工具返回结果**。只能向用户报告工具实际返回的信息（文件路径、成功/失败数量等），不得虚构进度百分比、文件大小或时长。
- **严格按四阶段顺序执行**：Phase 1 → Phase 2 → Phase 3 → Phase 4，每个阶段必须调用对应的专用工具，不可跳过或替代。

## 二、爆款动态漫画套路共识（必须遵守）

### 2.1 平台共性（B 站漫画、快看、抖音、快手、微短剧式动态漫）

- **前三秒/前 5 镜定生死**：第一集前 3 秒必须出现强视觉或强冲突（打斗/对峙/反转/高情绪台词），不能从平淡日常开篇。
- **单集结构**：引子（Hook）→ 铺垫/冲突升级 → 本集高潮画面 → 悬念/未解决冲突收尾，促进连播。
- **单集时长与格数**：短剧式 1–3 分钟/集常见；单集镜头/格数不宜过多，避免信息过载。每集至少一个"可截图传播"的高潮画面。
- **节奏**：快切、少长对白；长对白拆成多格+表情/动作配合；关键台词配合特写或动态强调。
- **结尾**：每集结尾必须有"未解悬念"或"下一集期待"（新人物登场、反转预告、危机升级）。

### 2.2 专业分镜师基本能力（必须体现）

- **景别与视角**：远景（环境/规模）→ 中景（对话/动作）→ 近景/特写（情绪/关键信息）；俯仰视用于权力感/压迫感/主角光环。
- **构图与视线引导**：三分法、留白、视线流向引导读者到下一格；重要信息与人物放在视觉焦点。
- **分格节奏**：紧张段落用多小格快切；情绪或爆点用大格/跨格；避免整集均匀分格无起伏。
- **对白精简**：小说长句改为短句、金句；心理描写转为表情/动作/环境；每格对白尽量控制在 1–2 句。
- **动态设计**：明确每格/每段的动效意图（推拉摇移、闪白、震动、速度线、残影等），便于后期实现。

## 三、可用工具

本技能通过 4 个工具分阶段执行，每阶段完成后等待用户确认再继续：

| 工具名 | 阶段 | 功能 |
|--------|------|------|
| `comic_storyboard_script` | 第一阶段 | 解析小说输入，生成结构化 JSON 分镜脚本（集→面板，含 image_prompt、对白、旁白） |
| `comic_storyboard_images` | 第二阶段 | 为每个面板生成 AI 漫画图片（Gemini T2I） |
| `comic_storyboard_tts` | 第三阶段 | 为每个面板的旁白/对白生成 TTS 语音 |
| `comic_storyboard_video` | 第四阶段 | 将图片 + 语音合成为每集 MP4 视频（ffmpeg） |

---

## 四、执行流程（严格四阶段）

### 第一阶段：生成分镜脚本

1. 从用户输入中提取小说内容。如果用户提到"用 bestseller-novel 的结果"，从对话历史中收集该技能的输出。
2. 确认目标参数（若用户未指定，使用默认值并告知）：
   - 平台：抖音（默认）
   - 画面比例：9:16 竖屏（默认）
   - 画风：国漫写实（默认）
   - 集数：根据内容量自动规划
3. 调用 `comic_storyboard_script`，传入 `novel_text` 和参数。
4. 向用户展示生成结果摘要：集数、每集面板数、角色列表、每集钩子与悬念。
5. **等待用户确认**后才进入下一阶段。用户可要求修改集数、节奏、角色等。

### 第二阶段：生成漫画图片

仅在用户确认分镜脚本后执行。

1. 调用 `comic_storyboard_images`。
2. 系统自动进行 prompt 增强，确保：
   - **场景锚定**：从每集首帧提取场景描述，注入后续所有面板，防止场景跳脱。
   - **角色一致性**：从 `characters[].visual_tags` 提取外貌标签，追加到每个面板 prompt。
   - **画风锁定**：强制 "illustration/manga style, NOT photorealistic" 指令，防止出现真人照片风格。
   - **禁止文字**：追加反文字指令，防止 T2I 在画面中生成汉字/水印。
3. 逐面板展示生成结果（图片+景别信息）。
4. **等待用户确认**。用户可要求重新生成某集的图片（使用 `episode_filter` 参数）。

### 第三阶段：生成 TTS 语音

仅在用户确认图片后执行。

1. 调用 `comic_storyboard_tts`。
2. 系统自动**按角色分配不同音色**（多音色 TTS）：
   - 从分镜脚本的 `characters` 列表自动推断性别，按性别分配不同声音。
   - 默认音色分配：旁白（沉稳男声 YunyangNeural）、男主（年轻男声 YunxiNeural）、男配/反派（成熟男声 YunjianNeural）、女性角色（柔美女声 XiaomoNeural）、系统音（中性女声 XiaoxiaoNeural）。
   - 说话人从 dialogue 的 `角色名(语气)：台词` 格式自动检测。
   - 如脚本 JSON 包含 `voice_map` 字段（角色名→TTS音色），则使用该显式映射。
3. 报告每集的语音生成结果（成功/失败/跳过数量，含角色与音色信息）。
4. 用户可通过 `voice` 参数统一覆盖所有角色音色（如 `zh-CN-YunxiNeural`）。
5. **等待用户确认**。

### 第四阶段：合成视频

仅在用户确认语音后执行。

1. 调用 `comic_storyboard_video`。
2. 视频自动包含：
   - **字幕烧录**：对白自动生成 ASS 字幕并烧入视频底部（仅显示角色对白，旁白不显示为字幕）。
   - **音画对齐**：每个面板的 TTS 音频自动匹配 `duration_s`（短则补静音，长则截断）。
   - **多比例支持**：支持 9:16、16:9、4:3、3:4、1:1、21:9 六种画面比例。
3. 展示每集视频文件路径和状态。
4. 用户可要求重新合成某集（使用 `episode_filter` 参数）。

---

## 五、特殊场景

- **用户只要分镜脚本**：完成第一阶段后，用户满意即可结束，无需继续。
- **用户只要图片**：完成前两阶段后结束。
- **用户只要脚本+语音（不要图片）**：跳过第二阶段，第一阶段后直接进第三阶段（TTS 不依赖图片）。
- **重新生成某一集**：各阶段都支持 `episode_filter` 参数，可单独重做一集。
- **更换音色**：第三阶段支持 `voice` 参数覆盖所有角色为统一音色；也可在脚本 JSON 中通过 `voice_map` 字段为每个角色指定音色。

---

## 六、输出格式约定

- **分镜脚本**（第一阶段）：JSON 格式，含集信息、面板详情、角色列表。
- **图片**（第二阶段）：每面板一张图片（URL 或 base64）。
- **TTS**（第三阶段）：每面板一个 MP3 音频文件。
- **视频**（第四阶段）：每集一个 MP4 视频文件（含字幕烧录、多角色音色、音画对齐）。
